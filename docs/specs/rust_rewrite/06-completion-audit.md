# Rust Rewrite Completion Audit

Status: **local runtime primitives are working; E2B/Cube compatibility is not
complete**.

This audit is the source of truth for whether the Rust rewrite can be described
as "fully working." It uses the current repository state, not spike intent.

## Explicit blocker disposition

| Blocker | Disposition |
|---|---|
| Public Rust crates landed | Yes, for the local runtime/library surface. |
| Snapshot/pause compatibility | VM primitive yes; E2B lifecycle scheduler substrate yes; concrete runtime-backed E2B compatibility no. |
| Large rootfs assembly | Multi-block-group images are implemented; production-template scale is still not fully proven because deeper extent trees, htree directories, metadata checksums, and journal behavior remain deferred. See `crates/ext4/DEFERRED.md`. |
| Egress policy | Request fields are modeled and the host runtime hard-fails unsupported policy requests; enforcement is not implemented. |
| Hostname/TLS | Host-header routing substrate exists, `fk e2b host` preflights local wildcard hostname resolution, and the domain proxy can serve HTTPS from operator-provided PEM certificate/key material. The vendored Rust SDK can add a trusted local CA/certificate by builder PEM or `E2B_CA_CERT_FILE`, and can preserve SDK-generated host-shaped HTTPS URLs while resolving those hosts to a local proxy listener through `sandbox_resolve_addr` or `E2B_SANDBOX_RESOLVE_ADDR`. Managed DNS and public/fleet trust distribution for non-local SDK traffic remain missing. |
